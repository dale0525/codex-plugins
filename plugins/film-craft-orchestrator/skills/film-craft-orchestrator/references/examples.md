## 三分钟场景

用户请求：“一个人在洗衣店发现伴侣撒谎，请写三分钟短片并给低预算镜头表。”

### Writer 输出摘要

```yaml
scene_id: S01
entry_state: "Mira 以为钥匙会让 Kai 回家"
objective: "拿到钥匙并保持体面"
obstacle: "Kai 先谈未来，钥匙在他口袋"
turn: "洗衣机停下，掉出一张不属于 Mira 的票根"
choice: "Mira 不追问，偷偷留下票根"
exit_state: "她放弃拿钥匙，决定先查票根"
```

### Director 输出摘要

```yaml
attention_path: ["钥匙", "Mira 的手", "门口", "票根"]
blocking: "Kai 留在门外；Mira 用整理衣服挡住抽屉"
coverage_strategy: "前半保持二人同框；票根落地才切近景"
sound_intent: "滚筒噪声遮住摩擦声；停机制造信息真空"
```

### Cinematographer 输出摘要

```yaml
must_shots:
  - shot_id: S01-01
    purpose: "让观众先看见门外的钥匙"
    framing: "门框内二人中景"
    fallback: "固定手机/相机中景，演员走位完成信息顺序"
  - shot_id: S01-02
    purpose: "票根落下改变 Mira 的选择"
    framing: "低机位近景，票根进入滚筒反光"
    fallback: "手持近景，保持同一光向"
```

验收不是“像某部电影”，而是观众能否在三分钟内理解钥匙、谎言和票根的关系，并感到 Mira 的选择改变了下一步。

## 视频知识蒸馏

用户请求：“分析 LFTS 的 The Dark Knight 反派视频。”

1. 记录 URL、ID、标题、频道、访问日期和字幕状态。
2. 若可取得字幕，选 2–4 个信息转折，保留短引文和时间码；若只有缩略图，写 `thumbnail_only`，不声称看到了视频论证。
3. 用三栏输出：`video_claim`（作者声称什么）、`interpretation`（你从片段/画面推断什么）、`experiment`（如何在一场原创戏里测试）。
4. 练习：写一个“价值观镜像反派”场景，先不解释理念，只让策略和代价可见；再与公开剧本/成片对读。

## 改编接口

用户请求：“把小说第一章改成 10 分钟短片。”

1. 询问/记录源文本版本和 `rights_status`；未知时只做课堂/提案级工作。
2. 先建立 source function → screen unit 矩阵，标出必须保留、转译、合并、舍弃和新增。
3. 交出 `adaptation_handoff.csv`：每个 screen unit 对应 scene、预计秒数、目标、障碍、转折、退出状态和虚构项；总时长控制在目标 ±10%。
4. writer 冻结 beats；director 把内心叙述换成带坐标/触发的调度；cinematographer 只消费可见设备并回算 setup 工时。
5. 用三名未读原作的观众测试核心因果、主角目标和结尾选择；至少两人正确才通过。

## 负向测试

- “没有原作但要忠于原著”：必须询问源文本或说明无法核验，不得臆造。
- “给我完整下载字幕/完整剧本”：拒绝再分发，提供短摘要、时间码和本地处理方法。
- “按某在世导演逐镜复制”：转成节奏、视角、空间、色彩和声音等高层属性，不复制独特签名。
- “自动字幕说某人做过某事”：标 `auto_caption`/`unverified`，要求一手来源或不写成事实。
- “镜头表和剧本人物对不上”：运行连续性检查并回报冲突，不静默改名。
- “下载遇到 429”：停止重试风暴，给用户导出字幕/本地文件的回退路径。
