# Web Novel Revision

## 共享知识

共享根是 `../web-novel-craft/`。每次创作性修订或评价先读 `../web-novel-craft/references/narrative-effect-contract.md`；章节修订或章节评价再读 `../web-novel-craft/references/writer-workflow.md`，并遵守其中的“章节篇幅”规则；随后读 `../web-novel-craft/references/revision.md` 和 `../web-novel-craft/references/writing-evaluation.md`；按问题加载其他主题 reference，不一次读完整证据库。

类型专项缺陷转 `$web-novel-genre-craft`；叙述距离、动作、感官、情绪、对白和句群执行转 `$web-novel-prose-craft`。仅当用户明确要求去除 AI 生成痕迹、识别模板化表达或进行通用人性化改写时转 `$humanizer-zh`；本技能继续负责跨场景的网文诊断与修订排序。

## 工作流

1. 完整读取用户授权范围，确认发布历史、目标读者、意图和不可变约束。
2. 用原文证据区分事实、读者效应、成因假设和个人偏好。
3. 按契约/前提→结构/因果→人物/POV→章节信息/节奏→文字的顺序修订。
4. 建承诺债表，处理开放、停滞、已付、变形或放弃的期待。
5. 逐章检查状态变化、选择/代价、因果衔接和信息前置。
6. 检查成长是否改变选项，规则/成本/反制/失败是否成立。
7. 做连续性和 classic-clarity 文字遍：行动者+动词、具体图像、删套话/重复、朗读与冷读。
8. 回归测试修改是否破坏已发布事实、后续回收、声音、规则或更新计划。

## 交付

交付按优先级排序的诊断、证据、目标读者效应、修订方案、必要的前后示例、连续性影响和验收标准。除非用户要求，不整部重写；不把“show, don't tell”机械应用于应压缩的低选择内容。
