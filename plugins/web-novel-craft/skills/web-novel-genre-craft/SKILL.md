# Web Novel Genre Craft

## 共享知识

共享根是 `../web-novel-craft/`。先读 `references/genre-craft.md`，再按任务加载 `xianxia-progression.md`、`urban-business.md`、`infinite-horror.md`、`ensemble-war-factions.md`、`science-fiction-worldbuilding.md`、`fanfiction-source-craft.md`、`female-revenge-era-rebirth.md`、`romance.md`、`mystery.md`、`comedy-dialogue.md`、`long-form-endings.md` 或 `historical-research.md`。

## 路由边界

- 本技能负责类型特有的读者承诺、事件语法与验收。
- 通用主线、卷章因果和节奏交给 `$web-novel-structure`；人物独立目标、声音与 POV 交给 `$web-novel-characters`。
- 用户主动询问实时平台门槛、合同或推荐机制时，说明它超出创作判断，并要求当前官方来源；不要主动扩展为发布管理。
- 多类型组合先声明主承诺、次承诺和结尾优先级，不能让支线无意间推翻主类型契约。

## 工作流

1. 写下类型、目标读者、主承诺、允许的变体和明确不承诺的体验。
2. 选择对应状态表：关系、谜题命题、喜剧 setup/payoff、对白权力与信息、历史场景证据。
3. 把类型阶段落到人物行动、信息变化、代价和后续压力，不把标签或氛围当推进。
4. 将外部主线与类型线编织到同一关键选择，避免两条故事轮流停摆。
5. 对长篇中段检查模式变化、承诺进展、升级维度与支线汇合；对高潮和结尾做准备—对抗—牺牲—余波审计。
6. 用类型专属反例测试：移除发糖是否仍有关系弧、揭晓后旧线索是否改义、笑点是否只有解释、历史细节是否改变场景选择。
7. 交付可复核的类型设计、失败信号、修复顺序、接受标准和仍需核实的经验性假设。

## 强制原则

- Romance 与“含爱情支线的其他类型”分开；若以 romance 宣传，先明确 HEA/HFN 或经用户确认的契约变体。
- Slow burn 必须产生因果动量；同一误会循环不是慢热。
- 悬疑反转要满足回溯公平：先前可见材料在答案后获得新意义，而不是答案临时引入。
- 喜剧模型来自单口或教学时只能迁移机制，不能把现场表演条件直接等同小说阅读。
- 对白潜台词同时记录表层意图、真实目标、权力、信息优势和回避动作。
- 历史资料按来源质量与场景用途记录；不知道时标记不确定，不用“时代感”掩盖时代错置。
- 中文“黄金三章”、追读和开篇经验是带日期、平台与样本边界的假设；只能辅助理解读者反应，不作为永久阈值。
- 同人和真人原型必须区分来源事实、推断与新创作，不复制来源表达，也不把 AI 推测冒充事实；用户另问现实权利问题时再查当前官方来源或建议专业意见。

## 交付

按任务交付类型契约、关系状态表、线索命题表、喜剧/潜台词卡、中段升级图、高潮与结尾回收表或历史场景证据卡。每项必须说明证据来自事实、作者选择还是待验证假设。
