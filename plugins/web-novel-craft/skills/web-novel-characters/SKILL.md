# Web Novel Characters

## 共享知识

共享根是 `../web-novel-craft/`。每次创作先读 `../web-novel-craft/references/narrative-effect-contract.md`，再读 `../web-novel-craft/references/characters.md`；需要续写记忆时读 `../web-novel-craft/references/story-bible.md`。

人物动机、视角与声音留在本技能；以 romance 类型承诺为核心的关系 beat、slow burn 与 HEA/HFN 验收转 `$web-novel-genre-craft` 并读 `../web-novel-craft/references/romance.md`。

## 工作流

1. 分别评估 empathy、rooting interest、progress，以及 likeability、proactivity、competence。
2. 连接经历→当下欲望→特有策略→关键选择→代价，不用背景说明代替决定。
3. 区分 flaw、limitation、handicap、wound 和 quirk，检查其是否真实影响选择。
4. 给重要配角和反派独立欲望、策略、知识边界与离场行动。
5. 选择服务信息控制与读者体验的 POV，明确距离和切换规则。
6. 从注意、遗漏、词汇、句法、隐喻、社交姿态和回避建立声音。
7. 用压力—选择—代价—新状态—再测试建立弧光。

## 诊断

- 主角被动：给反应明确优先级、策略和改变后续状态的选择。
- 动机单音：用冲突义务、新证据和代价显出不同侧面。
- 全能：限定能力领域，恢复成本、盲区和反制。
- 配角抢戏：兑现注意承诺或降低强调，不把“电话亭里的猩猩”留作装饰。
- 台词可互换：恢复人物欲望、知识、节奏、隐喻来源和回避方式。
- POV 泄漏：回到当前感知与推断，或建立明确叙事模式。

## 交付

交付人物卡、关系张力、知识边界、POV 规则、关键选择弧、声音样本及各吸引力轴的诊断。不要仿写在世作者的独特声音。

## 完成门

- 每个主要角色都有当下目标、策略、能力边界、盲区和至少一次压力下的选择/代价。
- POV、知识权限和声音规则能解释一个具体场景中的信息限制。
- 关系变化必须改变后续选择，而非只增加履历或口头禅。
- 检查通过后停止扩写；类型契约或局部句段问题转对应分技能。
