# 类型专项总则

类型不是元素清单，而是读者预期会被反复推进并在适当边界兑现的体验。先声明主类型承诺，再选择关系、谜题、喜剧、历史或长篇结尾的专用 artifact；混合类型必须记录主次与冲突解决顺序。

## 通用类型卡

```yaml
genre_contract:
  primary: romance|mystery|comedy|historical|other
  target_reader: concrete reading situation
  promised_experience: []
  required_payoffs: []
  allowed_variations: []
  explicitly_not_promised: []
  secondary_genres: []
  ending_priority: []
  evidence_status: author_choice|manuscript_fact|dated_hypothesis
```

## 共同程序

1. 将类型承诺写成读者可观察的状态、问题或情绪，不写成销售愿望。
2. 为每个篇章安排承诺的开启、进展、转义和回收，避免只在开头贴标签、结尾突然兑现。
3. 让类型线和外部主线在人物选择处相交；删除其中一条后若另一条毫无变化，说明尚未编织。
4. 用反例检查：没有发糖是否仍有关系变化；知道谜底后旧材料是否成立；去掉解释后笑点是否可见；删除历史细节是否改变选择。
5. 将视频比例、字数、人物数和平台指标保留为带来源日期的假设，只能通过当前作品与当前平台复测。

## 类型组合冲突

- 以 romance 为主时，HEA/HFN 是默认讨论起点；悲剧爱情应明确改写契约。人物负弧或开放结尾不能悄悄覆盖 romance 承诺。
- Slow burn 可以借阶段表导航，但没有统一时间点；重复误会不能因模板而获得正当性。
- 悬疑的缺席线索只改变概率，不能单独定罪；反转的双向线索必须经回溯公平测试。
- 单口喜剧的现场笑声、每分钟笑点和试演条件不能直接作为小说质量阈值。
- 中段九点结构的约八分之一节拍与“第四季度约最后20%”描述的是不同层级，不能合并成同一个强制比例。

## 证据边界

本组程序来自完整阅读的视频字幕或本地 ASR，详细来源见 `video-extension-knowledge-base.json`。它们主要是创作者教学、访谈、演示和个人平台经验，不是普遍因果证明。所有当前平台政策和指标都要向官方来源复核。
