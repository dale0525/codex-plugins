# Web Novel Prose Craft

## 共享知识

共享根是 `../web-novel-craft/`。场景总流程先读 `../web-novel-craft/references/scene-prose-craft.md`；再按问题加载 `../web-novel-craft/references/narrative-distance.md`、`../web-novel-craft/references/action-sensory-emotion.md`、`../web-novel-craft/references/dialogue-voice-rhythm.md` 或 `../web-novel-craft/references/ai-prose-diagnostics.md`。

## 路由边界

- 本技能负责已经明确“此场要发生什么”之后的叙述执行：视角落点、信息密度、动作、感官、情绪、对白、句群和段落。
- 场景没有人物选择、因果变化或类型功能时，先转 `$web-novel-structure`、`$web-novel-characters` 或 `$web-novel-genre-craft`，不能靠润色伪造戏剧作用。
- 全稿分层诊断、意见、修改排序和前后评价交给 `$web-novel-revision`；AI 草稿也按相同写作标准处理，不另建生产流程。

## 场景执行程序

1. 冻结本场入口状态、POV、即时欲望、阻力、信息权限、出口变化和下一压力。
2. 选择叙述距离；每次拉近或拉远都要服务信息、情绪或节奏，禁止无信号跳入他人内心。
3. 把关键变化写成动作—感官/身体—解释—选择—后果链；低选择、重复或过渡内容可概述，不机械执行 `show, don't tell`。
4. 动作场先固定空间、目标、限制与可用物，再按意图—动作—反馈—代价更新状态；招式名和形容词不能替代可视因果。
5. 情绪场先写触发与人物的具体解释，再给不完全受控的身体/注意反应和改变关系的选择；避免直接堆叠抽象情绪词。
6. 对白逐句检查表层目的、真实目标、信息优势、关系动作与反应；删问候和重复解释，但保留读者定位所需的最小标签。
7. 句群编辑先标相邻句的因果、转折、例证、递进或并行动作；用准确连接、语序、连动或必要短句控制重心，不照搬英语分词结构。
8. 在移动端宽度朗读，检查主语漂移、指代、欧化长句、同构句、段落墙、无意重复和刻意节拍是否被抹平。

## 强制原则

- “具体”不是形容词更多，而是读者能定位行动者、空间、刺激、身体、选择和状态变化。
- 五感按 POV 注意力和场景任务选择，不要求每场集齐五种；感官必须影响判断、动作或气氛。
- 快节奏是低困惑的高价值变化率；短句、空行和打斗本身不保证快。
- 概述与戏剧化都是工具：重要选择与不可逆变化通常展开，机械移动、重复过程和低价值时间可压缩。
- 不仿写在世作者的独特文风；只抽象讨论叙述距离、词汇具体度、句法、节奏和声音约束，帮助用户建立自己的 voice contract。
- 英语写作课与语文课只能迁移功能，不能冒充中文网文留存或商业效果的因果证据。

## 交付

交付场景合同、叙述距离图、动作/感官/情绪链、对白意图表、句群诊断、必要的局部改写、失败边界和盲读验收。若修改用户原文，说明每处修改解决的具体读者问题与可能损失。
